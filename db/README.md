# База данных «Эталон»

**Источник правды по структуре — папка `db/migrations/`.**
Одна таблица или изменение = один новый файл `V00X__описание.sql`. Больше ничего править не нужно.

```
db/
  migrations/        # пошаговые изменения (прод + локалка), по порядку V001, V002, V003 ...
  seed_dev.sql       # тестовые данные, ТОЛЬКО локально
  README.md
```

## Локальная база (Docker)

Собирается автоматически из миграций + `seed_dev.sql` (настроено в `docker-compose.yml`):

    docker compose down -v
    docker compose up -d

`down -v` сбрасывает том базы — при следующем старте миграции и сид накатываются заново.
Добавила новую таблицу → положила файл `V00X__...sql` в `db/migrations/` → `down -v && up`. Всё.

## Боевая база (сервер)

Накатывать новые миграции строго по порядку, каждую ОДИН раз. **Бэкап перед накаткой!**

    mysql -u ПОЛЬЗОВАТЕЛЬ -p ИМЯ_БД < db/migrations/V00X__....sql

или через phpMyAdmin → «Импорт». `V001` на рабочую базу не накатывать (её таблицы уже есть).

## Полная схема (schema.sql) — руками НЕ храним

Генерируем из базы, когда нужна «карта» всей структуры:

    docker compose exec -T db mysqldump -u etalon -petalon --no-data --skip-comments etalon > db/schema.sql

Флаги: `--no-data` — только структура; `--skip-comments` — без служебных комментариев.
