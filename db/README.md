# База данных «Эталон»

Структура и данные разнесены по двум файлам. Миграций больше нет — базу
накатываем на чистую БД целиком.

```
db/
  schema.sql   # ВСЯ структура: таблицы, индексы, внешние ключи, триггер справочника
  seed.sql     # данные: раздел 1 — базовые справочники и станки (нужны всегда),
               #         раздел 2 — тестовые данные (только для локальной разработки)
  README.md
```

## Порядок накатки (важен)

Сначала структура, потом данные:

    mysql -u ПОЛЬЗОВАТЕЛЬ -p ИМЯ_БД < db/schema.sql
    mysql -u ПОЛЬЗОВАТЕЛЬ -p ИМЯ_БД < db/seed.sql

## Локальная база (Docker)

Собирается автоматически из `schema.sql` + `seed.sql` (см. `docker-compose.yml`,
файлы монтируются в `/docker-entrypoint-initdb.d` как `01_schema.sql` и `02_seed.sql`):

    docker compose down -v
    docker compose up -d

`down -v` сбрасывает том базы — при следующем старте структура и данные накатываются заново.

## Боевая база (сервер)

`schema.sql` — на ЧИСТУЮ базу (он создаёт таблицы с нуля). Из `seed.sql` на проде
нужен только **раздел 1** (базовые справочники и станки); раздел 2 — тестовые данные,
на прод не грузить. Бэкап перед любыми изменениями структуры обязателен.

## Менять структуру

Правим прямо в `schema.sql` (отдельные файлы миграций не заводим). Новые
справочные значения — в раздел 1 `seed.sql`.
